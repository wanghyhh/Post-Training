# 工作文档

## 1 任务描述

- 本项目旨在完成一套基于 DPO（Direct Preference Optimization，直接偏好优化）方法的大模型后训练的 python 实现，使用 Hugging Face 生态，基于 Lora 方法实现高效参数微调。
- DPO 属于**离线偏好优化**方法：它不训练独立的奖励模型，也不需要设计任何奖励函数，而是直接使用（prompt, chosen, rejected）偏好数据对，通过最大化"优选回答"与"劣选回答"之间的对数概率差，隐式地拟合出奖励函数，从而绕开显式奖励建模与在线采样两个环节。
- DPO 训练过程中需要保持一份**冻结的参考模型**（reference model），用于提供对数概率基准；参考模型与策略模型同源（即训练开始前的初始权重），训练全程不更新其参数。
- 偏好数据中的 chosen / rejected 必须是针对同一 prompt 的两个回答，二者构成一个偏好对；模型学到的"偏好信号"完全来自这种成对比较，因此数据的构造质量直接决定训练效果。
- 项目需包含大模型训练脚本、大模型评估脚本、配置文件、示例数据集、工具脚本。
- 训练及评估脚本需要能够直接在本地 Windows 电脑上的名为 cuda118env 的 conda 环境下使用 python 命令直接运行。
- 评估脚本需要能够 Linux 系统的服务器容器上使用 python 命令直接运行。
- 训练脚本需要能够 Linux 系统的服务器容器上使用 accelerate 命令运行，当显卡数量大于 1 时采用数据分片。
- 所有和环境相关的名称不能暴露在代码和数据集中。

## 2 目录结构

- 根目录`./`下： 训练及评估配置文件（Config.yaml）、accelerate配置文件（accelerate_config.yaml）、训练脚本（train.py）、工具脚本（tool_dpo.py）、模型评估脚本（evaluate_model.py）、训练过程绘制脚本（plot.py）
- 示例数据集目录`./example_data/`下： 示例训练数据集文件（data_train.jsonl）、示例测试数据集文件（data_test.jsonl），两个文件均为**偏好对数据**（每个样本包含同一 prompt 对应的 chosen 与 rejected 两条回答）。
- 输出目录`./output/`下： 所有脚本产生的输出、过程文件、临时文件都放置在这个文件夹下特定的子目录（如 logs/、checkpoints/、final_model/、eval/、plots/ 等）。
- **说明**：DPO 不依赖奖励函数，因此本项目**不含**奖励函数脚本（reward_function.py），配置文件中也**不含**奖励函数相关的命名对象与配置项。

## 3 任务要求

1. 训练及评估配置文件（Config.yaml）：
	- 所有在模型及数据集读取、训练、保存、评估等过程中需要修改的超参数、模型及数据集目录、训练配置等设置项全部暴露于本文件中，其余文件从本文件读取来获得。
	- 所有设置项按功能及过程的区别分类为不同的命名对象，利于人类阅读和修改。
	- 每个命名对象和具体配置项需配有注释说明用途。
	- Hugging Face 库中的训练器（trainer）类的配置项单独使用一个命名对象 TrainConfig 来定义，在训练脚本中读取为一个字典对象，并使用`train_args = DPOConfig(**TrainConfig, ... )`方式直接整体传入。以保持本配置文件和训练器配置项输入参数的格式统一。
	- 训练器配置需覆盖 DPO 的核心参数：其中 **beta 为偏好强度（温度）参数**，用于控制策略模型相对参考模型的偏离幅度——值越大越保守、越贴近参考模型，值越小越激进，典型取值范围 0.1~0.5。注意不同训练方法中 beta 的语义不同，迁移配置时不可直接照搬其他方法的数值。
	- 训练器配置需覆盖**偏好损失类型**（loss_type，如 sigmoid 原版损失、ipo、hinge 等）与**标签平滑**（label_smoothing）等 DPO 特有参数。
	- 训练器配置需包含序列长度相关参数：最大总长度、最大 prompt 长度、最大回答长度，以及超长样本的截断方向（truncation_mode）。
	- 训练器配置可包含参考模型对数概率预计算开关（precompute_ref_log_probs）等显存/速度权衡参数，并配有用途注释。
	- 数据集配置中需要包含训练数据集和测试数据集的路径。
	- 数据集配置中需要分别指定训练数据集和测试数据集中数据的使用率，默认为1，即使用数据集文件中100%的样本。
	- 数据集配置中需要指定验证集的占比，后续将按照这个比例从指定的训练数据集中划分训练集和验证集。
	- **不得包含在线生成类配置项**，例如每个 prompt 的生成次数、生成采样参数（temperature/top_p）、奖励函数配置对象（RewardFuncConfig）等。DPO 训练不做在线生成、不做组内相对比较，这些机制一律不适用。
	- 绘图配置单独使用一个命名对象 PlotConfig 来定义，包含：子图列数、子图垂直间距、子图水平间距、总标题 Y 轴位置、从第几步开始绘制（跳过前 N 步）、采样步长（滑动窗口平滑）以及输出图像的文件名与分辨率等设置，供绘图脚本读取。
2. accelerate配置文件（accelerate_config.yaml）：
	- 需支持在海光服务器的 DCU 显卡上运行。
	- 服务器为1台机器4张显卡。
3. 训练脚本（train.py）：
	- 仅有一个主函数，其余函数、类、工具等定义放到工具脚本（tool_dpo.py），保持代码简洁。
	- 主函数内按步骤组织代码，各步骤需包含详细的注释。
	- 自定义训练器的训练时的日志回调类，训练时打印过程信息，并保存为训练过程jsonl文件，保存路径为输出目录下的子文件夹。
	- **训练过程日志内容契约**：日志 jsonl 的每一行是一个 JSON 对象（回调在每一步结束时序列化训练器的 logs 字典），必须包含 step、epoch、timestamp 及该步全部指标。其中 `rewards/chosen`、`rewards/rejected`、`rewards/margins`、`rewards/accuracies` 是 DPO 隐式奖励在训练器日志中的标准键名——隐式奖励 = beta ×（策略对数概率 − 参考对数概率），由训练器内部自动计算，不涉及任何外部奖励函数，键名须与训练器实际输出保持一致（绘图脚本按此读取，不可改名）。训练指标至少包含：loss、rewards/chosen、rewards/rejected、rewards/margins、rewards/accuracies、logps/chosen、logps/rejected、grad_norm、learning_rate、nll_loss（仅在启用 rpo_alpha 时产生，无则省略）；其中 **step_time 训练器不会自动提供，必须由回调自行计算**（相邻两次日志记录之间的墙钟时间差，单位秒/步，首条记录置 0 或空）。
	- **评估结果写入日志**：每次评估（训练开始与每个 epoch 后）的指标同样由回调写入 jsonl，字段带 `eval_` 前缀（如 eval_loss、eval_rewards/chosen、eval_rewards/margins、eval_rewards/accuracies、eval_logps/chosen、eval_logps/rejected），与训练指标行共存于同一文件并携带对应 step，供绘图脚本按 §3.6 映射配对绘制。
	- 每次训练的日志jsonl都单独保存为一个文件，文件名中附带上训练时间（如 `train_log_20260902_115858.jsonl`）。
	- 同时维护一个统一的当前训练日志接口文件 `train_log.jsonl`：训练每一步结束后，先追加写入时间戳日志文件，再将 `train_log.jsonl` 的内容同步为与时间戳日志文件完全一致（即清空后重写），使得 `train_log.jsonl` 始终包含最新一次训练的完整日志。
	- 训练过程绘制脚本直接读取 `train_log.jsonl` 进行绘图，无需自动匹配最新文件。
	- 在训练开始和每轮epoch完成后都跑一次评估，即将训练器的"eval_strategy"设为"epoch"，将"eval_on_start"参数设为True。
	- 训练使用 Lora 方法，训练过程中和结束后需要能够自动保存模型和训练检查点，模型的保存方式均为保存 Lora 适配器，为了节省空间不要保存全部模型权重，保存路径为输出目录下的子文件夹。
	- **偏好对数据的加载与格式化**：从 jsonl 读取偏好数据后，需按训练器要求的字段组织样本（prompt 文本或 messages 列表 + chosen + rejected），并按 chat 模板渲染；assistant 内容必须分别落在 chosen 与 rejected 中，不得把两条回答混在同一个 messages 列表里。
	- **参考模型的处理**：使用 Lora 微调时，由训练器依据 PEFT 配置自动构造参考模型（前向时临时禁用适配器），无需额外加载第二份完整模型权重；若改为全量微调，则需显式传入与策略模型同源的参考模型。
	- 脚本运行时需要打印简洁明了的信息，所有打印信息保存风格统一（如 `[train][step=100][epoch=1/3] loss=0.42 rewards/margins=0.11 rewards/accuracies=0.63 grad_norm=0.85 lr=1e-4` 一类定长格式）。
	- 打印时机与内容：训练开始时打印配置概要（模型路径、数据集路径与样本数/使用率、LoRA 配置、beta/loss_type、batch size、总步数与 epoch 数等）；训练中周期性打印训练指标（每个 epoch 至少一次，步数多时可每 N 步一次，不得淹没输出）；每次评估完成后打印该次评估的全部 eval 指标；训练结束时打印总耗时与总步数。以上打印只由主进程（rank 0）执行。
	- 当脚本使用 accelerate 命令运行时，请注意协调主进程和其他进程之间功能，不要出现冗余操作、竞态操作等危险行为，例如多个进程都打印过程信息。
4. 工具脚本（tool_dpo.py）：
	- 所有其他脚本中的函数和类都在此文件中定义。
	- 所有其他脚本中能够实现封装的功能都在此文件中封装。
	- **注意**：DPO 不使用奖励函数，本文件以及项目其他文件中均**不包含**奖励函数类、奖励分量计算或奖励加权组合等逻辑；评估所需的偏好得分统一由模型自身对 chosen/rejected 的对数概率推导得到。
5. 模型评估脚本（evaluate_model.py）：
	- 该脚本作为一个例外，在该脚本内部实现大模型的评估函数和评估报告输出函数，并在主函数中调用，不用将函数放到工具脚本中；
	- 评估指标需要基于 **DPO 的偏好判别特性**，包含：偏好准确率（preference_accuracy，即模型给 chosen 的隐式奖励高于 rejected 的偏好对占比）、平均奖励间隔（avg_reward_margin，chosen 隐式奖励与 rejected 隐式奖励之差的均值）、chosen 平均隐式奖励、rejected 平均隐式奖励、奖励间隔分布统计（min/25%/中位数/75%/max）、平均对数概率（chosen 与 rejected 各自的平均 log 概率）、偏好对样本数与平均序列长度、评估速度（samples/s 或 pairs/s），以及各奖励分项（chosen/rejected/margin）的平均值与标准差。
	- 报告中的隐式奖励指标按两种视角分别给出：**相对参考模型视角**（隐式奖励 = beta × (logπ_θ − logπ_ref)，DPO 隐含奖励）与**策略自身概率视角**（logπ_θ(chosen) − logπ_θ(rejected)，不依赖参考模型）；两种视角均输出偏好准确率、平均奖励/概率间隔等核心指标，避免只看单侧数值而误判。
	- 报告还需包含：chosen 与 rejected 各自的平均序列长度（token 数，用于排查长度偏差）、偏好对判定分布（chosen 胜出/落败/持平各多少对，持平的判据为奖励间隔绝对值小于极小阈值）、以及**基座模型与微调后模型的指标对照表**（同一测试集上两列指标并列并给出差值 Δ，如准确率提升、平均奖励间隔提升），用于直观评价 DPO 微调带来的偏好判别能力提升。
	- 评估过程采用**分 Batch 并行前向策略**：将偏好对按 batch 组装后一次性送入模型，批量计算 chosen 与 rejected 的对数概率，避免逐条前向带来的效率损失，同时控制显存占用。
	- **偏好得分驱动评估**：评估逻辑围绕隐式奖励展开，隐式奖励由 `beta × (logπ_θ(chosen) − logπ_ref(chosen))` 一类对数概率差推导；评估脚本需能同时给出相对参考模型与相对策略模型自身概率的两种视角，避免只看单侧数值而误判。
	- **显存与模型适配**：评估逻辑需具备显存优化意识，支持 PEFT/LoRA 适配器的切换（使用 `set_adapter` 加载微调后的适配器），并能处理 Batch 前向过程中的 OOM 情况（遇到 OOM 时自动减小 Batch 并跳过）。
	- 该脚本的主函数包含两个步骤：基座模型、微调后模型评估。每次评估都调用评估函数完成，每次评估完成后都调用评估报告输出函数，将结果输出为输出目录下评估子文件夹下的 markdown 文件。
	- 评估函数的返回值为保存多个评估指标及评估结果的字典，并作为评估报告输出函数的输入参数，评估报告输出函数将评估指标及评估结果以规范的语言写入到 markdown 文件。
	- 待评估的大模型路径、测试数据集路径、是否评估基座模型、是否评估微调后模型等配置参数都放到训练及评估配置文件中，单独使用一个命名对象 EvalConfig 来定义。EvalConfig 还需包含**参考模型路径**配置项（DPO 的参考模型即训练前的基座权重，评估"相对参考模型视角"时必须加载；默认与基座模型路径一致，评估 Lora 微调结果时需加载基座权重并临时禁用适配器）。
	- 评估配置中**不需要**每个 prompt 的生成次数、采样温度、核采样阈值等生成类参数（DPO 评估不做自由生成）；若确需抽样生成做定性检查，应作为独立步骤单独配置，不与偏好指标混在同一处。
	- 生成样例展示要求：在评估报告（markdown 文件）的偏好对样例部分，必须直接打印模型的原始输入，即包含 system、user、assistant 等角色标签的完整文本（经过 `tokenizer.apply_chat_template` 渲染后的结果），chosen 与 rejected 两条回答需分别渲染、分别展示，不得只显示处理后的纯文本内容。这样可以在检查样例时直观看到模型接收到的完整 prompt 格式以及两条候选回答的完整上下文，便于排查数据格式、角色标签、截断等问题，同时对照展示同一偏好对的两个隐式奖励与奖励间隔。模型输出中尾部多余的重复角色标签（如多个 "assistant"）仍需在后处理中 strip 掉，但角色标签前缀和正文内容必须完整保留。样例展示的偏好对数量由 EvalConfig 控制（默认 3~5 对），建议同时覆盖判定正确与判定错误的偏好对，便于分析失败原因。
6. 训练过程绘制脚本（plot.py）：
	- 该脚本位于项目根目录（与训练、评估脚本同级），用于绘制训练过程的可视化曲线，从训练器输出的训练过程jsonl文件中提取训练/评估指标，使用 matplotlib 库生成多子图训练曲线图。
	- 日志指标映射（param_mappings）需对应 DPO 训练器的实际日志字段，包含：loss（对应 eval_loss）、rewards/chosen（对应 eval_rewards/chosen）、rewards/rejected（对应 eval_rewards/rejected）、rewards/margins（对应 eval_rewards/margins）、rewards/accuracies（对应 eval_rewards/accuracies，即偏好准确率）、logps/chosen（对应 eval_logps/chosen）、logps/rejected（对应 eval_logps/rejected）、nll_loss（对应 eval_nll_loss，仅在启用 rpo_alpha 时产生，缺失时自动跳过）、grad_norm（无 eval）、learning_rate（无 eval）、step_time（无 eval，绘制累计耗时曲线）；训练器其余输出字段（如 logits/chosen 等）存在时同样纳入映射。
	- **子图布局约定**：绘图脚本按固定规划生成多子图（子图列数由 PlotConfig 控制），各子图内容为：① loss（训练 loss 与 eval_loss）；② 奖励曲线（rewards/chosen、rewards/rejected、rewards/margins 及其 eval 对应项）；③ 偏好准确率（rewards/accuracies 及其 eval 对应项）；④ 对数概率（logps/chosen、logps/rejected 及其 eval 对应项）；⑤ nll_loss（整列缺失时跳过该子图）；⑥ 梯度与学习率（grad_norm 与 learning_rate 共用一图、双 y 轴）；⑦ 累计耗时（step_time 累加为分钟）。横轴统一为训练步（step）；eval 指标按日志携带的 step 以带标记的散点或虚线叠加在同一子图上，图例区分 train/eval。
	- **双层曲线展示思想**：在启用采样平滑（`stride > 1`）时，采用"原始曲线做底，平滑曲线置顶"的视觉方案。使用极浅透明度（`alpha=0.2`）的原始数据作为背景，叠加较高透明度（`alpha=0.8`）的滑动窗口平均曲线，以便在观察整体趋势的同时保留原始波动信息。
	- **时间效率可视化**：针对 `step_time` 指标，采用**累计耗时（分钟）**的逻辑进行绘制，并在曲线末端自动标注训练的总时长与总步数，用于直观评估训练效率。
	- 绘制函数需要包含参数：子图列数、子图垂直间距、子图水平间距、总标题 Y 轴位置、从第几步开始绘制（跳过前 N 步）、采样步长（滑动窗口平滑）。从训练及评估配置文件读取。
	- 绘制的图像文件输出到输出目录下的 `plots/` 子文件夹。

## 5 自动验收标准

- 验收运行脚本前必须先检查语法是否正确以及各文件格式是否符合要求。
- 完成所有文件的生成后，在本地 Windows conda 环境下使用 python 命令运行训练脚本、模型评估脚本、训练过程绘制脚本，确保正常运行。
- 本地电脑的显存有限，测试运行时可将训练及评估配置文件配置为节省显存的状态（例如减小 batch、开启参考模型对数概率预计算、缩短最大序列长度）。
- 确保训练脚本、模型评估脚本、训练过程绘制脚本运行时的过程信息打印内容无异常。
- 确保训练脚本、模型评估脚本、训练过程绘制脚本运行输出的所有文件无异常。
- 检查训练脚本在训练时打印的训练过程信息，确保其符合正常、有效训练时的数据情况：DPO 训练中 loss 应呈下降趋势、rewards/margins（优选与劣选的隐式奖励差）应逐步增大、rewards/accuracies（偏好准确率）应从接近随机的水平逐步上升；若上述三项全程无变化，说明偏好数据或训练配置存在问题而非训练本身波动。
- 检查训练过程日志 jsonl：字段完整（含 step_time 及各项 rewards/logps 指标）、训练与 eval 行共存；绘图脚本能据此生成全部规划子图且曲线非空。
- 项目完全情况及验收结果输出为一份markdown文件，保存在项目根目录`./`下。
- 验收的过程和结论输出为一份验收报告保存为 验收报告.md。

## 6 注意事项

以下为 DPO 训练脚本构建中的共性注意事项，适用于任意基座模型和任务场景。

### 6.1 训练

- **偏好对数据格式**：样本需明确区分 prompt（或 messages）与两条回答 chosen / rejected。若采用 messages 形式，chosen 与 rejected 各自是一条完整的对话列表，不要把二者塞进同一个列表；从 prompt 重建 messages 时注意不要多加一层嵌套（`[[{...}]]`），否则 `batched=True` 时 `msg_list[0]` 返回 list 而非 dict，导致 chat template 渲染失败。正确写法：`[{"role":"user",...}, {"role":"assistant",...}]`，assistant 内容为空占位。
- **beta 的语义与取值**：DPO 的 beta 是偏好温度参数，值越小对偏好信号越激进，训练越容易过拟合于数据中的偏好模式；值越大则越保守。迁移配置时需注意不同方法中 beta 的语义差异。
- **参考模型与显存**：DPO 前向需要同时经过策略模型与参考模型，显存占用约为普通 SFT 的两倍。Lora 微调时由训练器自动以"关闭适配器"的方式复用同一份基座权重作为参考模型，无需手动加载；若开启参考模型对数概率预计算，则可在训练前一次性算好并缓存，显著降低训练期显存，但代价是数据或参考模型变更后缓存失效，必须重新计算。
- **截断方向（truncation_mode）**：序列超长时，`keep_end` 保留尾部（更适合回答内容位于末尾的场景），`keep_start` 保留开头。截断会直接破坏偏好对语义，因此最大长度配置应尽量覆盖真实样本长度。
- **偏好损失类型与标签平滑**：`loss_type` 默认为 sigmoid（原版 DPO），另有 ipo / hinge 等变体；标签平滑（label_smoothing）可缓解偏好数据中的噪声。切换 loss_type 后，loss 的绝对量级不再可直接比较。
- **TrainerCallback 兼容性**：自定义回调必须继承 `TrainerCallback` 基类，显式实现所有用到的钩子方法（`on_init_end`/`on_train_begin`/`on_train_end`/`on_log`/`on_evaluate`）。注意不同版本中 `Control` 类的导入路径可能变化。
- **DPO batch size 约束**：DPO 每个样本已包含 chosen 与 rejected 两条序列，单条样本的实际计算量约为普通样本的两倍，配置 `per_device_train_batch_size` 时需按此估算显存；DPO 不做在线生成，**不存在**"batch size 必须能被生成数整除"的约束。
- **tqdm 进度条干扰**：tqdm 在 stderr 上反复覆盖输出，会淹没 stdout 的训练过程日志。推荐禁用 tqdm 或使用静默包装类，同时保留模块结构（如 `thread_map`/`process_map`）以满足框架内部导入需求。
- **padding 方向**：DPO 训练不使用在线生成，训练阶段统一使用 `padding_side='right'` 即可；仅当评估阶段需要自由生成做定性检查时，才临时切换为 `left`，生成结束后恢复。

### 6.2 配置与保存

- **LoRA 适配器保存**：训练结束后仅保存 LoRA 适配器（~几十 MB），不保存完整模型权重。部署时与基座模型合并加载即可。
- **训练元信息持久化**：每次训练结束后自动保存训练元信息文件（如 `train_meta.json`，位于输出目录下的 logs/ 子文件夹，含起止时间、模型标识、样本数、beta 与 loss_type 等 DPO 关键参数、LoRA 参数、训练参数等），用于训练复盘和复现。
- **Config 约束一致性**：`load_best_model_at_end: true` 要求 `save_strategy` 与 `eval_strategy` 匹配（同为 `"epoch"` 或 `"best"`），错误组合会触发 `ValueError`。
- **最佳模型指标的方向**：`metric_for_best_model` 应选用 DPO 实际产生的指标（如偏好准确率或验证 loss），并同步设置 `greater_is_better`——准确率类指标越大越好，loss 类指标越小越好，方向设反会导致保存到最差检查点。

### 6.3 评估

- **隐式奖励的判定基准**：偏好准确率以"chosen 的隐式奖励 > rejected 的隐式奖励"为通过条件，隐式奖励由策略模型与参考模型的对数概率差乘以 beta 得到；参考模型缺失或未正确加载时，该差值会退化为常数，表现为准确率恒为 0.5 附近且奖励间隔恒为 0，可用于判断接线是否正常。
- **评估时的参考模型加载**：评估脚本必须加载与训练时同源的参考模型（基座权重）来计算"相对参考模型视角"的隐式奖励；Lora 微调结果评估时，策略模型加载适配器、参考模型保持基座权重（禁用适配器），二者不可复用同一权重实例。
- **长度偏差**：隐式奖励是序列上对数概率的累加，序列越长数值越不稳定，跨样本直接比较绝对值意义有限。评估时应同时给出平均对数概率，并优先关注奖励间隔（同一偏好对内两条回答的相对差）而非绝对奖励值。
- **生成时 OOM 处理**：批量前向时需捕获 `RuntimeError`（OOM），自动跳过当前 batch 并清理显存缓存，避免整个评估流程中断。
- **基座与微调模型的对比意义**：基座模型未见过偏好数据，其偏好准确率应接近随机水平（约 50%）；微调后模型若明显高于该基线，说明偏好信号已被有效学习。若两者几乎相同，优先检查数据格式与适配器是否真正加载（`set_adapter`）。

### 6.4 绘图

- **日志路径容错**：绘图脚本读取日志时，应兼容不同的输出目录结构（如根目录下和子目录下两种 log 路径），避免路径硬编码。
- **耗时指标的数据来源**：`step_time` 不是训练器自带的日志字段，依赖训练回调自行测量后写入；若日志中该列整列缺失，绘图脚本应跳过累计耗时子图而非报错中断。
- **图例警告**：部分指标（如 `grad_norm`/`learning_rate`/`step_time`）无 eval 对应项，仅含单侧数据时 `ax.legend()` 会报 `No artists with labels found`，属正常现象可忽略；`nll_loss` 在未启用 rpo_alpha 时整列缺失，绘图前应先过滤空指标。
- **绘图降采样**：训练步数较多时使用 `stride` 滑动窗口降采样。推荐"原始线 `alpha=0.2` + 平滑线 `alpha=0.8`"的双层视觉方案。
- **matplotlib 字体兼容**：避免使用系统中可能不存在的中文字体，改用通用字体（如 `DejaVu Sans`），确保跨平台渲染一致。
