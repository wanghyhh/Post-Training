# 工作文档

## 1 任务描述

- 本项目旨在完成一套基于 SFT 方法的大模型后训练的 python 实现，使用 Hugging Face 生态，基于 Lora 方法实现高效参数微调。
- 项目需包含大模型训练脚本、大模型评估脚本、配置文件、示例数据集、工具脚本。
- 训练及评估脚本需要能够直接在本地 Windows 电脑上的名为 cuda118env 的 conda 环境下使用 python 命令直接运行。
- 评估脚本需要能够 Linux 系统的服务器容器上使用 python 命令直接运行。
- 训练脚本需要能够 Linux 系统的服务器容器上使用 accelerate 命令运行，当显卡数量大于 1 时采用数据分片。
- 所有和环境相关的名称不能暴露在代码和数据集中。

## 2 目录结构

- 根目录`./`下： 训练及评估配置文件（Config.yaml）、accelerate配置文件（accelerate_config.yaml）、训练脚本（train_sft.py）、工具脚本（tool_sft.py）、模型评估脚本（evaluate_model.py）、训练过程绘制脚本（plot_sft.py）
- 示例数据集目录`./example_data/`下： 示例训练数据集文件（data_train.jsonl）、示例测试数据集文件（data_test.jsonl）。
- 输出目录`./output/`下： 所有脚本产生的输出、过程文件、临时文件都放置在这个文件夹下特定的子目录（如 logs/、checkpoints/、final_model/、eval/、plots/ 等）。

## 3 任务要求

1. 训练及评估配置文件（Config.yaml）：
	- 所有在模型及数据集读取、训练、保存、评估等过程中需要修改的超参数、模型及数据集目录、训练配置等设置项全部暴露于本文件中，其余文件从本文件读取来获得。
	- 所有设置项按功能及过程的区别分类为不同的命名对象，利于人类阅读和修改。
	- 每个命名对象和具体配置项需配有注释说明用途。
	- Hugging Face 库中的训练器（trainer）类的配置项单独使用一个命名对象 TrainConfig 来定义，在训练脚本中读取为一个字典对象，并使用`train_args = SFTConfig(**TrainConfig, ... )`方式直接整体传入。以保持本配置文件和训练器配置项输入参数的格式统一。
	- 数据集配置中需要包含训练数据集和测试数据集的路径。
	- 数据集配置中需要分别指定训练数据集和测试数据集中数据的使用率，默认为1，即使用数据集文件中100%的样本。
	- 数据集配置中需要指定验证集的占比，后续将按照这个比例从指定的训练数据集中划分训练集和验证集。
2. accelerate配置文件（accelerate_config.yaml）：
	- 需支持在海光服务器的 DCU 显卡上运行。
	- 服务器为1台机器4张显卡。
3. 训练脚本（train_sft.py）：
	- 仅有一个主函数，其余函数、类、工具等定义放到工具脚本（tool_sft.py），保持代码简洁。
	- 主函数内按步骤组织代码，各步骤需包含详细的注释。
	- 自定义训练器的训练时的日志回调类，训练时打印过程信息，并保存为训练过程jsonl文件，保存路径为输出目录下的子文件夹。
	- 每次训练的日志jsonl都单独保存为一个文件，文件名中附带上训练时间（如 `train_log_20260902_115858.jsonl`）。
	- 同时维护一个统一的当前训练日志接口文件 `train_log.jsonl`：训练每一步结束后，先追加写入时间戳日志文件，再将 `train_log.jsonl` 的内容同步为与时间戳日志文件完全一致（即清空后重写），使得 `train_log.jsonl` 始终包含最新一次训练的完整日志。
	- 训练过程绘制脚本直接读取 `train_log.jsonl` 进行绘图，无需自动匹配最新文件。
	- 在训练开始和每轮epoch完成后都跑一次评估，即将训练器的"eval_strategy"设为"epoch"，将"eval_on_start"参数设为True。
	- 训练使用 Lora 方法，训练过程中和结束后需要能够自动保存模型和训练检查点，模型的保存方式均为保存 Lora 适配器，为了节省空间不要保存全部模型权重，保存路径为输出目录下的子文件夹。
	- 脚本运行时需要打印简洁明了的信息，所有打印信息保存风格统一。
	- 当脚本使用 accelerate 命令运行时，请注意协调主进程和其他进程之间功能，不要出现冗余操作、竞态操作等危险行为，例如多个进程都打印过程信息。
4. 工具脚本（tool_sft.py）：
	- 所有其他脚本中的函数和类都在此文件中定义。
	- 所有其他脚本中能够实现封装的功能都在此文件中封装。
5. 模型评估脚本（evaluate_model.py）：
	- 该脚本作为一个例外，在该脚本内部实现大模型的评估函数和评估报告输出函数，并在主函数中调用，不用将函数放到工具脚本中；
	- 评估指标需要包含 loss、PPL 等，以及其他有意义的指标。
	- 该脚本的主函数包含两个步骤：基座模型、微调后模型评估。每次评估都调用评估函数完成，每次评估完成后都调用评估报告输出函数，将结果输出为输出目录下评估子文件夹下的 markdown 文件。
	- 评估函数的返回值为保存多个评估指标及评估结果的字典，并作为评估报告输出函数的输入参数，评估报告输出函数将评估指标及评估结果以规范的语言写入到 markdown 文件。
	- 待评估的大模型路径、测试数据集路径、是否评估基座模型、是否评估微调后模型等配置参数都放到训练及评估配置文件中，单独使用一个命名对象 EvalConfig 来定义。
	- 生成样例展示要求：在评估报告（markdown 文件）的生成样例部分，必须直接打印模型的原始输入和原始输出，即包含 system、user、assistant 等角色标签的完整文本（经过 `tokenizer.apply_chat_template` 渲染后的结果），不得只显示处理后的纯文本内容。这样可以在检查样例时直观看到模型接收到的完整 prompt 格式以及生成内容的完整上下文，便于排查数据格式、角色标签、生成截断等问题。模型输出中尾部多余的重复角色标签（如多个 "assistant"）仍需在后处理中 strip 掉，但角色标签前缀和正文内容必须完整保留。
6. 训练过程绘制脚本（plot_sft.py）：
	- 该脚本位于项目根目录（与训练、评估脚本同级），用于绘制训练过程的可视化曲线，从训练器输出的训练过程jsonl文件中提取训练/评估指标，使用 matplotlib 库生成多子图训练曲线图。
	- 绘制函数需要包含参数：子图列数、子图垂直间距、子图水平间距、总标题 Y 轴位置、从第几步开始绘制（跳过前 N 步）、采样步长（滑动窗口平滑）。从训练及评估配置文件读取。
	- 绘制的图像文件输出到输出目录下的 `plots/` 子文件夹。

## 6 注意事项

以下为 SFT 训练脚本构建中的共性注意事项，适用于任意基座模型和任务场景。

### 6.1 训练与评估

- **自定义损失函数注入 token 级指标**：HuggingFace Trainer 默认仅记录 loss/grad_norm/learning_rate 等基础指标。如需记录 token 级指标（如 entropy、token 准确率），需通过 `compute_loss_func` 自定义损失函数，在其中自算交叉熵并累积指标。
- **训练/评估状态判断**：评估时 `labels` 仍存在（评估数据集包含 labels），**不能**用 `labels is not None` 判断训练/评估状态，必须通过 `model.training` 属性判断。否则评估行的 token 指标会错误累积到训练分支。
- **生成文本尾部标签清理**：`model.generate()` 可能输出尾部重复角色标签（如 `assistant\nassistant`），需在 `tokenizer.decode()` 后进行 strip 处理。
- **生成时 padding 方向**：decoder-only 架构生成时必须使用 `padding_side='left'`。loss 计算阶段可用 `right` padding，但生成前需临时切换，否则影响生成质量并产生警告。

### 6.2 配置与保存

- **Config 约束一致性**：`load_best_model_at_end: true` 要求 `save_strategy` 与 `eval_strategy` 匹配（同为 `"epoch"` 或同为 `"best"`）。错误组合（如 `save_strategy: "steps"` + `load_best_model_at_end: true`）会触发 `ValueError`。
- **LoRA 适配器保存**：训练结束后仅保存 LoRA 适配器（~几十 MB），不保存完整模型权重（~数 GB）。部署时与基座模型合并加载即可。
- **检查点自动查找**：评估时若未指定检查点路径，应自动扫描 `output_dir` 下 `checkpoint-*` 目录，按步数排序取最新。

### 6.3 多卡训练

- **主进程保护**：多进程运行时需通过 `local_rank == 0` 或 `args.is_main_process` 判断，仅主进程执行日志写入、模型保存、终端打印等操作，避免冗余和竞态。注意：`is_main_process` 不是 `TrainerCallback` 的直接属性，需从 `args` 或 `state` 获取。
- **accelerate 配置**：多卡训练需配置 `accelerate_config.yaml`，指定 `distributed_type`、`num_processes`、`mixed_precision` 等参数。启动命令为 `accelerate launch --config_file accelerate_config.yaml train_sft.py`。

### 6.4 训练日志与绘图

- **双文件日志机制**：每次训练生成独立时间戳日志文件（`train_log_YYYYMMDD_HHMMSS.jsonl`），同时维护统一接口文件（`train_log.jsonl`）。绘图脚本固定读取统一接口文件，无需自动匹配最新文件。
- **日志解析一致性**：不同指标可能在同一步骤产生多条 log 事件，绘图解析时必须用 `(step, value)` 配对列表确保 x/y 数据长度严格一致，避免错位。
- **绘图降采样**：训练步数较多时使用 `stride` 滑动窗口降采样避免曲线过密。推荐"原始线 `alpha=0.2` + 平滑线 `alpha=0.8`"的双层视觉方案，兼顾波动细节与趋势可读性。
- **matplotlib 字体兼容**：避免使用系统中可能不存在的中文字体（如 SimHei/微软雅黑），改用通用字体（如 `DejaVu Sans`），确保跨平台渲染一致。
